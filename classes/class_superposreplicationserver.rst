SuperposReplicationServer
=========================

**Inherits:** :ref:`RefCounted<class_RefCounted>` **<** :ref:`Object<class_Object>`

Authority-side fan-out of one canonical World to authenticated client links.

.. rst-class:: classref-introduction-group

Description
-----------

Replicates every live object of one configured :ref:`SuperposSession<class_SuperposSession>` (the World) to each attached link Session, one per client. A link is a separate :ref:`SuperposSession<class_SuperposSession>` configured with the same schemas and authority epoch and connected to the client through :ref:`SuperposSession.configure_udp()<class_SuperposSession_method_configure_udp>` with replication routes: channel 0 a control channel, channels 1 and 2 reliable unordered. The client attaches a :ref:`SuperposSpawner<class_SuperposSpawner>` to its own Session.

Each link runs the native sender store and replication bridge: spawn binding and initial baseline, atomic state publications of up to 16 objects, ownership resets, leaves and full repairs on request, with retransmission and receipts owned by native delivery. Owner-only fields are hidden from peers that do not own the object, and authority-only fields are never sent. Wire revisions are per link and strictly increasing, so an atomic group is never partially stale. Native work is bounded by four in-flight captures per link; refused work is retried on the next :ref:`publish()<class_SuperposReplicationServer_method_publish>`. No script, getter, setter or user callback runs in the publish path. The World and link Sessions are weak native identities.

Relevance: every object belongs to a region (0 by default). Region 0 is visible to every link; a link with an interest filter (:ref:`set_peer_interest()<class_SuperposReplicationServer_method_set_peer_interest>`) also sees its interest regions and nothing else, and replicas that leave its interest are retired. Enrollment walks the region index one region per publish, so a link never scans the whole World. A dormant object keeps its replicas but publishes no state until it is woken. Pending publications are ordered by priority weight times age within an optional per-link byte budget. Objects in one explicit group (at most 16 objects and 64 KiB of state) publish together in one atomic message, and only once every replicated member is ready. After a large publication the link promotes the object's baseline to the published state (at most twice per second per object), so later deltas stay small.

Typed RPCs: :ref:`send_rpc()<class_SuperposReplicationServer_method_send_rpc>` calls a registered schema RPC on one link's replica, and :ref:`read_rpcs()<class_SuperposReplicationServer_method_read_rpcs>` returns client calls, each authorized at that moment against the live World: declared RPC, payload bound, authority epoch and permission (Owner calls also require the current ownership revision). Rejected calls are counted, never delivered. Incoming data never selects a method, script or resource.

Per link at most 1000 replicas are active and 64 lifecycle transitions are pending. Objects beyond that are deferred until capacity frees. Paired RTC links are not supported yet and return :ref:`@GlobalScope.ERR_UNAVAILABLE<class_@GlobalScope_constant_ERR_UNAVAILABLE>`.

All methods are main-thread and owner-thread only. GDScript, C# and C++ call the same native ClassDB implementation.

::

    var server := SuperposReplicationServer.new()
    server.configure(world)
    server.attach_peer(link) # link: a configure_udp server Session for one client
    # Every frame, after canonical writes to the World:
    server.publish()
    link.advance_tick()

.. _class_SuperposReplicationServer_method_attach_peer:

.. rst-class:: classref-method

:ref:`Error<enum_@GlobalScope_Error>` **attach_peer**\ (\ link\: :ref:`SuperposSession<class_SuperposSession>`, configuration\: :ref:`Dictionary<class_Dictionary>` = {}\ ) :ref:`🔗<class_SuperposReplicationServer_method_attach_peer>`

Reserves every native pool for ``link`` and starts replicating to it once its Session is admitted. The link must have a native UDP association, the World's exact schema fingerprint and authority epoch, and no attached receiver. Accepted integer keys are ``peer`` (defaults to the admitted remote peer), ``replica_epoch`` (default 1, must match the client's receiver), ``maximum_active`` (1 through 1000), ``maximum_transitions`` (1 through 64), ``scan_budget`` (World slots visited per publish when enrolling objects, 1 through 100000, default 4096), ``control_channel``, ``state_channel`` and ``bulk_channel`` (defaults 0, 1 and 2), ``rpc_channel`` (default 3, reliable ordered), ``state_budget`` (delta and repair bytes queued per publish, 0 for unbounded, at most 1 MiB) and ``baseline_promotion`` (1 by default, 0 disables). Unknown keys return :ref:`@GlobalScope.ERR_INVALID_PARAMETER<class_@GlobalScope_constant_ERR_INVALID_PARAMETER>`. Generic packet methods on the link reject the three replication channels from attachment.

Selects the World Session to replicate. Accepted keys are ``maximum_peers`` (1 through 256, default 32), ``maximum_regions`` (1 through 65536, default 256) and ``maximum_per_region`` (objects one region can hold, 1 through 4096, default 1000). .. _class_SuperposReplicationServer_method_publish:

.. rst-class:: classref-method

:ref:`Dictionary<class_Dictionary>` **publish**\ (\ ) :ref:`🔗<class_SuperposReplicationServer_method_publish>`

Reads the World once and queues lifecycle, repair and state work on every attached link. Call once per frame after the World's canonical writes and before the links advance. Returns ``error``, ``peers``, ``stepped``, ``waiting`` (links not yet admitted), ``busy``, ``failed``, ``dropped`` (links freed or reconfigured, removed from the server) and ``tick``. A link that fails with a protocol or capacity error records it as its network error and stops.

Takes at most ``maximum`` (at most 64) client RPCs from ``link``, each a Dictionary with ``handle``, ``rpc_id``, ``sender``, ``ownership_revision`` and ``payload``. Every call is authorized when it is taken (execution time); rejected calls are counted in :ref:`read_peer_status()<class_SuperposReplicationServer_method_read_peer_status>` under ``rpc`` and discarded. The inbox holds at most 64 calls and 64 KiB; further calls wait in the ordered channel.
