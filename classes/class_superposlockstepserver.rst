SuperposLockstepServer
======================

**Inherits:** :ref:`RefCounted<class_RefCounted>` **<** :ref:`Object<class_Object>`

Server half of deterministic input streaming: per-peer jitter buffers in, delta-compressed command stream out.

.. rst-class:: classref-introduction-group

Description
-----------

Accepts each client's redundant input batches into a per-slot adaptive playout buffer and releases one input per server tick, two while catching up, none while buffering. Starvation raises a slot's target depth; a calm buffer slowly lowers it again. A tick lost beyond the client's redundancy is skipped and counted, never invented. The server records every slot's consumed input with :ref:`begin_tick()<class_SuperposLockstepServer_method_begin_tick>`, :ref:`set_command()<class_SuperposLockstepServer_method_set_command>` and :ref:`end_tick()<class_SuperposLockstepServer_method_end_tick>`. :ref:`pack_commands()<class_SuperposLockstepServer_method_pack_commands>` then encodes only the inputs that changed, for every tick after the one a client last acknowledged, so all clients can advance the same deterministic world.

::

    var lockstep := SuperposLockstepServer.new()
    lockstep.configure(4, 101, {"initial_target": 6})
    # On a received input payload from player slot s:
    lockstep.accept_inputs(s, payload)
    # Every server tick:
    lockstep.begin_tick(tick)
    for s in 101:
        for item in lockstep.consume_inputs(s):
            lockstep.set_command(s, item.input)
    lockstep.end_tick()
    var batch := lockstep.pack_commands(lockstep.get_playout_status(s).command_acknowledged)
    if batch.error == OK:
        session.enqueue_packet(batch.payload, COMMAND_CHANNEL)

Methods must be called on the owning thread.

Sets the fixed input width (1-16 bytes), the slot count (1-256) and optional playout tuning: ``initial_target`` (default 6 ticks), ``minimum_target`` (2), ``maximum_target`` (45, below 128), ``relax_ticks`` (240) and ``catch_up_margin`` (12), and command-stream sizing: ``command_history_ticks`` (128, up to 65536) is the window in which a slow joiner or a stalled client catches up without another keyframe, ``command_change_capacity`` (0 sizes for every slot changing on every retained tick) caps the shared change entries, and :ref:`pack_stream()<class_SuperposLockstepServer_method_pack_stream>` policy: ``stream_redundant_ticks`` (1), ``stream_catch_up_ticks`` (30) and ``stream_resync_backlog_bytes`` (0, off: a client whose unacknowledged backlog exceeds this many encoded command bytes is reported stale, so a keyframe resync replaces replaying a backlog larger than a keyframe) and ``stream_resync_holdoff_ms`` (30000: the advice waits this long after each keyframe reset, so a keyframe still crossing a slow link is not followed by another). History is allocated once here. Unknown keys return :ref:`@GlobalScope.ERR_INVALID_PARAMETER<class_@GlobalScope_constant_ERR_INVALID_PARAMETER>`.

Encodes every sealed tick after ``after_tick`` that fits whole in ``max_bytes``. Each changed slot travels as a slot gap, a changed-byte mask and only the changed bytes. With ``recipient`` set to a slot, that slot's processed client ticks (see :ref:`set_command()<class_SuperposLockstepServer_method_set_command>`) ride along so a predicting client reconciles without stamping ticks into its broadcast input. Returns ``error`` and ``payload``. :ref:`@GlobalScope.ERR_DOES_NOT_EXIST<class_@GlobalScope_constant_ERR_DOES_NOT_EXIST>` means the requested ticks were evicted; send :ref:`pack_keyframe()<class_SuperposLockstepServer_method_pack_keyframe>` together with a world snapshot instead.

.. _class_SuperposLockstepServer_method_step_commands:

.. rst-class:: classref-method

:ref:`Array<class_Array>` **step_commands**\ (\ tick\: :ref:`int<class_int>`, hold_mask\: :ref:`PackedByteArray<class_PackedByteArray>`, merge_mask\: :ref:`PackedByteArray<class_PackedByteArray>`\ ) :ref:`🔗<class_SuperposLockstepServer_method_step_commands>`

One deterministic server tick for every slot: consumes each playout, merges the ``merge_mask`` bits of all inputs consumed in a catch-up tick into the newest, holds the newest input masked by ``hold_mask`` for starved ticks (zero before the first input), records every slot's command with its processed client tick and seals the tick. Both masks are one byte per input byte. Returns one :ref:`PackedByteArray<class_PackedByteArray>` input per slot for the game step.

.. _class_SuperposLockstepServer_method_pack_command_window:

.. rst-class:: classref-method

:ref:`Dictionary<class_Dictionary>` **pack_command_window**\ (\ acknowledged_tick\: :ref:`int<class_int>`, sent_tick\: :ref:`int<class_int>`, max_bytes\: :ref:`int<class_int>` = 880, recipient\: :ref:`int<class_int>` = -1, redundant_ticks\: :ref:`int<class_int>` = 0\ ) |const| :ref:`🔗<class_SuperposLockstepServer_method_pack_command_window>`

Fresh-first streaming for unreliable channels. Encodes every tick after ``sent_tick`` that fits whole in ``max_bytes``, then uses remaining space for up to ``redundant_ticks`` already-sent ticks after ``acknowledged_tick``, so an isolated lost batch heals without a round trip while fresh ticks never starve. With nothing fresh it resends the newest unacknowledged ticks. Returns ``error`` and ``payload`` like :ref:`pack_commands()<class_SuperposLockstepServer_method_pack_commands>`; rewind ``sent_tick`` to ``acknowledged_tick`` when acknowledgements stall for longer than a round trip.

.. _class_SuperposLockstepServer_method_pack_stream:

.. rst-class:: classref-method

:ref:`Dictionary<class_Dictionary>` **pack_stream**\ (\ slot\: :ref:`int<class_int>`, srtt_usec\: :ref:`int<class_int>`, max_bytes\: :ref:`int<class_int>` = 880\ ) :ref:`🔗<class_SuperposLockstepServer_method_pack_stream>`

Next command batch for ``slot``'s client, from its own native sender state: fresh-first windows carrying its processed ticks, an immediate repair from its acknowledgement when it reports holding ticks beyond it (a lost batch), one rewind after a stall of 2 x ``srtt_usec`` plus its ack cadence, and ``stream_redundant_ticks`` of redundancy only while it is within ``stream_catch_up_ticks`` of the newest tick and its stream has seen loss recently (a long clean stream drops redundancy to halve bandwidth). Pass the session's ``smoothed_rtt_us``. Returns ``error`` and ``payload``; :ref:`@GlobalScope.ERR_DOES_NOT_EXIST<class_@GlobalScope_constant_ERR_DOES_NOT_EXIST>` means its acknowledgement left history: send a keyframe and call :ref:`reset_stream()<class_SuperposLockstepServer_method_reset_stream>`.
