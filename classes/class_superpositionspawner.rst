SuperpositionSpawner
====================

**Inherits:** :ref:`Node<class_Node>` **<** :ref:`Object<class_Object>`

Automatic authoritative scene spawning, ownership and lifecycle.

.. rst-class:: classref-introduction-group

Description
-----------

Replicates the membership of allowlisted local scenes. Add below a :ref:`SuperpositionWorld<class_SuperpositionWorld>`, assign :ref:`scenes<class_SuperpositionSpawner_property_scenes>`, and choose :ref:`spawn_path<class_SuperpositionSpawner_property_spawn_path>`. The server calls :ref:`spawn()<class_SuperpositionSpawner_method_spawn>`; compatible clients instantiate their own matching scene. Export-stable scene manifests include prefab IDs, local resource identity, node structure, declared script method/property interfaces and nested property schemas. They do not hash script implementation bytes; use game_protocol and a build-version contract to reject incompatible gameplay implementations. Mismatching peers fail closed. Spawn envelopes carry bounded scalar metadata, not scene paths or objects. Nested :ref:`Superposition<class_Superposition>` components receive stable per-instance keys. Ownership uses the authenticated client identity associated with a live connection, while recipient and visibility APIs use connection-generation peer IDs.

.. _class_SuperpositionSpawner_method_spawn:

.. rst-class:: classref-method

:ref:`int<class_int>` **spawn**\ (\ prefab_id\: :ref:`int<class_int>`, owner_peer\: :ref:`int<class_int>` = -1, data\: :ref:`Dictionary<class_Dictionary>` = {}\ ) :ref:`🔗<class_SuperpositionSpawner_method_spawn>`

Server-only: creates a membership entity and local instance for an allowlisted ``prefab_id``. ``owner_peer`` is a currently admitted server peer ID, or -1 for server ownership; its authenticated client identity is stored with the instance. ``data`` allows at most 16 string keys (64 UTF-8 bytes each), with null, Boolean, integer, finite float, finite Vector3 or strings of at most 256 UTF-8 bytes. The complete envelope must fit 4096 bytes. Returns a positive entity handle on success or 0 and :ref:`spawn_error<class_SuperpositionSpawner_signal_spawn_error>` on failure. Metadata is attached as superposition_spawn_data and passed to :ref:`spawned<class_SuperpositionSpawner_signal_spawned>`.
