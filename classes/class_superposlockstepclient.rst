SuperposLockstepClient
======================

**Inherits:** :ref:`RefCounted<class_RefCounted>` **<** :ref:`Object<class_Object>`

Client half of deterministic input streaming: redundant tick inputs out, relayed command stream in.

.. rst-class:: classref-introduction-group

Description
-----------

Records exactly one fixed-width input per simulation tick and packs every input the server has not yet reported received, so inputs survive loss on an unreliable :ref:`SuperposSession<class_SuperposSession>` channel. In the other direction it applies the server's delta-compressed command stream (one input per player slot per tick) strictly in order, letting the client advance the same deterministic world as the server, for example an :ref:`EGPBox3DWorld<class_EGPBox3DWorld>`. Each packed input batch also reports the newest command tick received here in order, which tells the server which ticks it no longer needs to resend.

::

    var lockstep := SuperposLockstepClient.new()
    lockstep.configure(4, 101)                 # 4-byte inputs, 101 player slots
    lockstep.load_keyframe(join_table)         # or start from tick 1 with an all-zero table
    # Every simulation tick:
    lockstep.record_input(tick, my_input)
    session.enqueue_packet(lockstep.pack_inputs(), INPUT_CHANNEL)
    # On each received command payload:
    lockstep.accept_commands(payload)
    while lockstep.advance_command() != 0:
        for slot in 101:
            apply_input(slot, lockstep.get_input(slot))
        world.step_tick(world.get_tick() + 1)

Methods must be called on the owning thread.

:ref:`Error<enum_@GlobalScope_Error>` **accept_commands**\ (\ payload\: :ref:`PackedByteArray<class_PackedByteArray>`\ ) :ref:`🔗<class_SuperposLockstepClient_method_accept_commands>`

Buffers a relayed command batch. Ticks already received are ignored. A batch that starts after a gap returns :ref:`@GlobalScope.ERR_UNAVAILABLE<class_@GlobalScope_constant_ERR_UNAVAILABLE>`; the client must load a keyframe. Malformed payloads return :ref:`@GlobalScope.ERR_INVALID_DATA<class_@GlobalScope_constant_ERR_INVALID_DATA>` and change nothing.

:ref:`Error<enum_@GlobalScope_Error>` **configure**\ (\ input_bytes\: :ref:`int<class_int>`, slots\: :ref:`int<class_int>`, buffer_ticks\: :ref:`int<class_int>` = 128\ ) :ref:`🔗<class_SuperposLockstepClient_method_configure>`

Sets the fixed input width (1-16 bytes), the number of player slots (1-256) shared with the server, and how many received command ticks may wait ahead of the simulation. A batch that would overflow the buffer is rejected whole and resent later. Reconfiguring discards all retained inputs and commands.

.. _class_SuperposLockstepClient_method_pack_inputs:

.. rst-class:: classref-method

:ref:`PackedByteArray<class_PackedByteArray>` **pack_inputs**\ (\ max_ticks\: :ref:`int<class_int>` = 60, max_bytes\: :ref:`int<class_int>` = 880\ ) |const| :ref:`🔗<class_SuperposLockstepClient_method_pack_inputs>`

Packs the newest unacknowledged inputs that fit in ``max_bytes``, up to ``max_ticks``, so a saturated uplink never resends an ever-growing backlog; older inputs the server never received are skipped by its playout. Size ``max_ticks`` to the redundancy you want (for example half a second of ticks). The default stays inside one unreliable Superpos datagram. Returns an empty array when unconfigured.
